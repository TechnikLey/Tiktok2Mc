## 🔴 REQUIRED — Release Blockers

### 1. End-to-End Update Validation
The single highest-risk item. Update has 50+ unit/integration tests but the compiled `update.exe → start.exe → restart` flow has never been exercised across actual version boundaries.
- Test with real compiled binaries across a simulated v0.x → v1.0.0 upgrade
- Verify: file signaling, API kill signal fallback, config whitelist preservation, rollback on interruption, Windows/Linux path correctness
- **Risk:** A broken update path on compiled build prevents users from ever receiving fixes and could corrupt installation

### 2. Documentation Rewrite (DO LAST — after all code changes frozen)
- `GUIDE.md` is stale: missing event bus routing, hook system, declarative plugin subscriptions
- `CHANGELOG.md` test count and date need updating
- `README.md` should mention API server access and actions editor

## 🟡 HIGH — Should Ship Before v1.0.0

### 3. Plugin Dependency Ordering
`depends_on` declared in `plugin.json` manifests but never checked by launcher or API. Plugins start in whatever order `start.py` iterates. Timer depends on WinCounter (`auto_win`) but this is not enforced.

### 4. Config Decoupling — `minecraft_server_api`
`minecraft_server_api` section still lives in `defaults/config.yaml` (plugin-specific settings in main config). Should move to plugin-local config or a dedicated `plugins/minecraft_server_api/` directory.

### 5. Build System Hardening
- Add CI build step on PRs (not just tags) — compile at least one exe to catch PyInstaller regressions early
- `upload.py` is generated by `build.py` with stale version if not rebuilt — consider removing from git and generating during CI

---

## 🟢 MEDIUM — Nice to Have

### 6. Update Check UI
Backend endpoints exist (`GET /api/v1/updates/check`, `GET /api/v1/plugins/updates`). `start.py` already calls plugin updates at startup. Missing: any frontend element to display or trigger update checks.

### 7. `core_hash` Build Cache Optimization
Any change to any file in `src/core/**/*.py` invalidates all cached executables. Correct but wasteful for single-plugin changes. Could be refined to only invalidate dependent exes.

### 8. Declarative Command Handler Registration
`comment_commands` still has hardcoded `handler: http` + `url:` for Spotify in `defaults/config.yaml`. Plugins should register their own command handlers dynamically via API instead of URLs being baked into main config.
